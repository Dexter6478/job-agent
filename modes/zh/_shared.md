硬规则：

- 可以重组、压缩、改写关键词，但不能虚构经历、指标、项目、证书或实习。
- 候选人是软件工程本科实习求职者，不是高级工程师、架构师、AI PM 或顾问。
- 不代表候选人点击投递、发送消息或提交表单。

## 中国软件工程本科实习岗位评分体系

岗位匹配使用 **100 分制**。所有岗位分析必须输出 **综合评分：0-100**，并拆分为以下五项。每一项都必须写明得分原因，不能只给总分。

固定输出格式：

| 评分项 | 满分 | 得分 | 原因 |
|---|---:|---:|---|
| 技术匹配 | 40 |  |  |
| 项目匹配 | 25 |  |  |
| 岗位质量 | 15 |  |  |
| 成长空间 | 10 |  |  |
| 城市/实习条件 | 10 |  |  |
| 综合评分 | 100 |  |  |

### 1. 技术匹配：40 分

| 子项 | 分值 | 评价标准 |
|---|---:|---|
| Java / Spring Boot | 15 | 是否要求 Java、Spring Boot、Spring MVC、RESTful API、后端业务逻辑；候选人是否有图书管理系统中的 Java/Spring Boot 项目支撑 |
| 数据库 | 10 | 是否要求 MySQL/PostgreSQL、表设计、SQL、索引、事务；候选人是否有 PostgreSQL 表设计、事务、行级锁经验可迁移 |
| Redis | 5 | 是否要求缓存、验证码、限流、防刷、状态管理；候选人是否有 Redis 验证码和频率限制经验 |
| AI 应用 | 10 | 是否要求 LLM API、Prompt Engineering、RAG、Agent、AI安全；候选人是否有 Dietapp 的 AI 安全分析和 Prompt Injection 风险识别经验 |

### 2. 项目匹配：25 分

评价：
- JD 是否能直接匹配到 `cv.md` 中的真实项目。
- 候选人的个人贡献是否清楚。
- 项目是否能支撑面试追问。
- 是否有可讲的技术决策，例如事务控制、行级锁、Redis 限流、幂等提交、AI 安全分级。

### 3. 岗位质量：15 分

重点识别风险：
- 培训岗、招生岗、转培训、先交费或诱导贷款。
- 外包低质量岗位、长期驻场但 JD 含糊。
- “AI应用开发”实际是运营、标注、销售、客服或低代码工具推广。
- 标题写 Java/AI，但 JD 没有具体技术栈、业务场景或项目职责。
- 实习岗位要求接近高级工程师或全职主力，但薪资/培养机制不匹配。

### 4. 成长空间：10 分

评价：
- 是否有真实开发任务。
- 是否能学习后端工程、数据库、Redis、AI 应用或前后端协作。
- 是否有导师、团队协作、代码评审、项目迭代机会。
- 是否有转正或长期培养可能。没有写明则标记未知，不猜测。

### 5. 城市 / 实习条件：10 分

评价：
- 城市是否在 `config/profile.yml` 的优先或可接受城市中。
- 是否说明实习周期、每周到岗天数、到岗时间、是否可远程/混合。
- 不要假设候选人能接受未列出的城市。

### 分数解释

| 分数 | 投递建议 |
|---:|---|
| 85-100 | 推荐投递。高度匹配，应尽快沟通 |
| 70-84 | 推荐投递。匹配良好，但需针对短板准备话术 |
| 55-69 | 谨慎投递。可作为补充机会，先确认岗位真实性和实习条件 |
| 0-54 | 不推荐。匹配弱、风险高或不适合本科实习阶段 |

## 技能匹配置信度

每次岗位分析必须输出技能匹配置信度，分为三类：

### 明确匹配

JD 要求与 `cv.md` 中技能或项目经历直接对应。

示例：
- JD 要求 Spring Boot；`cv.md` 中图书管理系统明确使用 Spring Boot。
- JD 要求 Redis；`cv.md` 中 Dietapp 明确实现 Redis 验证码和限流。

### 相关匹配

JD 要求与 `cv.md` 中经验属于相近生态或可迁移经验，但不能等同为熟练掌握。

示例：
- JD 要求 Python；`cv.md` 中有 FastAPI 项目经验，可说明“FastAPI 属于 Python 生态相关经验”，但不能直接写“Python 熟练”。
- JD 要求 MySQL；`cv.md` 中 PostgreSQL 更明确，可说明“数据库设计、事务、索引经验可迁移”，但不能直接写“大量 MySQL 项目经验”。

### 未知缺失

JD 要求在 `cv.md` 中没有明确或相关依据。

示例：
- Kafka
- Docker/Kubernetes
- Elasticsearch
- 微服务治理
- 模型训练

硬规则：
- 禁止把“相关匹配”写成“明确匹配”。
- 禁止把“了解”写成“熟练”。
- 禁止把没有项目依据的技能写成项目经验。
- 对未知缺失项，要给出复习或沟通策略，而不是编造。

## 角色画像

每个 JD 必须归类为以下一种或两种混合画像：

| 画像 | JD 信号 |
|---|---|
| Java后端开发实习 | Java、Spring Boot、Spring MVC、MySQL、Redis、RESTful API、后端接口、业务逻辑、事务 |
| AI应用开发实习 | LLM API、RAG、Agent、Prompt、AI应用、FastAPI、智能问答、知识库、AI安全 |
| 全栈开发实习 | 前后端分离、Vue3、React Native、TypeScript、接口联调、管理端页面 |
| 不适合岗位 | 培训、销售、客服、运营、标注、外包驻场含糊、无技术职责 |

## 中国互联网实习招聘输出原则

1. 输出使用中文，技术名词保持常见写法，如 Spring Boot、RESTful API、Redis、RAG。
2. 以本科实习求职为中心，关注基础、项目、可培养性和面试可讲性。
3. 不使用高级岗位表达，例如“架构设计负责人”“技术战略”“企业级转型”。
4. 对 MySQL 与 PostgreSQL 的关系要诚实：可以说 PostgreSQL 经验可迁移，但不要说有大量 MySQL 项目经验。
5. 对 AI 方向要诚实：可以说了解 LLM API、RAG、Agent、Prompt Engineering、AI安全；不能说有模型训练、算法研究或大规模 LLMOps 经验，除非 `cv.md` 明确写了。
6. 风险判断必须具体，不要泛泛而谈“公司不错/岗位不错”。
7. BOSS/牛客/拉勾沟通话术应短、真实、像学生本人发出的消息。

## 必须输出的信息

中文 JD 分析必须包含：
- 岗位基本信息
- 技术要求分析
- 技能匹配置信度：明确匹配 / 相关匹配 / 未知缺失
- 0-100 匹配评分和五项分项得分
- 匹配优势
- 技术短板
- 推荐简历版本：只能是 Java后端版、AI应用版、全栈版、无推荐简历版本
- 投递建议：只能是 推荐投递、谨慎投递、不推荐
- BOSS沟通开场白或岗位真实性确认问题
- 预计面试问题

如果投递建议为 **不推荐**：
- 推荐简历版本必须输出：**无推荐简历版本**。
- 不要生成正常求职话术。
- 改为生成“岗位真实性确认问题”，用于确认是否真实研发岗位、是否涉及实际开发、是否有导师指导、是否收费/培训。

## 面试问题生成规则

如果岗位偏 Java：
- Java 基础
- Spring Boot
- MySQL
- Redis
- 事务
- 项目追问

如果岗位偏 AI：
- LLM
- RAG
- Prompt
- Agent
- AI安全
- FastAPI / PostgreSQL / Redis 如何支撑 AI 应用

问题必须围绕 `cv.md` 中真实项目展开。
