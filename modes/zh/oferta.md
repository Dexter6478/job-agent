# 模式: job -- 中国软件工程实习 JD 分析

当候选人输入中文 JD、岗位链接、BOSS/牛客/拉勾文本或本地 JD 文件内容时，使用本模式进行分析。

本模式面向：
- 软件工程本科生
- Java后端开发实习
- AI应用开发实习
- 全栈开发实习

必须读取：
- `cv.md`
- `config/profile.yml`
- `modes/_profile.md`
- `modes/zh/_shared.md`

不要编造候选人经历。不要使用高级岗位、架构师、专家、顾问式表达。

---

# 岗位分析

## 基本信息

用表格输出：

| 字段 | 内容 |
|---|---|
| 公司 | 从 JD 提取；没有则写“未提供” |
| 岗位 | 从 JD 提取 |
| 城市 | 从 JD 提取；没有则写“未提供” |
| 平台 | BOSS直聘 / 牛客 / 拉勾 / 公司官网 / 未知 |
| 岗位画像 | Java后端开发实习 / AI应用开发实习 / 全栈开发实习 / 不适合岗位 |
| 实习条件 | 实习周期、每周到岗天数、到岗时间；没有则写“未提供” |

---

## 技术要求分析

将 JD 要求拆成表格：

| JD 要求 | 是否匹配 | cv.md 中的依据 | 说明 |
|---|---|---|---|

匹配判断使用：
- 高匹配
- 部分匹配
- 不匹配
- JD 未提及

必须覆盖这些方向，如果 JD 未提及也要标明：
- Java / Spring Boot / Spring MVC
- MySQL / PostgreSQL
- Redis
- RESTful API / 前后端分离
- FastAPI
- LLM API / RAG / Agent / Prompt Engineering / AI安全

---

## 技能匹配置信度

必须按以下三类输出：

### 明确匹配

列出 JD 中与 `cv.md` 直接对应的技能或项目经验。

示例：
- Spring Boot：图书管理系统中明确使用 Spring Boot 提供 RESTful API。

### 相关匹配

列出可迁移但不能等同的技能。

示例：
- Python：`cv.md` 中有 FastAPI 项目经验，可视为 Python 生态相关经验，但不能直接写“Python 熟练”。
- MySQL：`cv.md` 中 PostgreSQL、事务、行级锁经验可迁移，但不能直接写“大量 MySQL 项目经验”。

### 未知缺失

列出 JD 要求但 `cv.md` 没有依据的技能。

示例：
- Kafka、Docker、Kubernetes、Elasticsearch、模型训练等。

禁止把相关匹配当作明确匹配。禁止把“了解”写成“熟练”。

## 我的匹配评分

输出 **综合评分：0-100 分**，并且必须拆分五项得分。

使用 `modes/zh/_shared.md` 中的 100 分体系：

| 维度 | 分值 | 得分 | 理由 |
|---|---:|---:|---|
| 技术匹配 | 40 |  |  |
| 项目匹配 | 25 |  |  |
| 岗位质量 | 15 |  |  |
| 成长空间 | 10 |  |  |
| 城市/实习条件 | 10 |  |  |
| 总分 | 100 |  |  |

评分必须保守、可解释。若 JD 信息不足，不能给满分，应在岗位质量或实习条件中扣分。

输出时必须明确写：

```text
综合评分：XX/100
```

## 匹配优势

列出 3-5 条。

每条必须包含：
- 对应 JD 要求
- `cv.md` 中的真实依据
- 面试时可怎么讲

优先从这些真实项目中提取：
- 智能饮食健康管理系统 Dietapp
- 图书管理系统

## 技术短板

列出 2-5 条。

规则：
- 只指出相对于 JD 的差距。
- 不贬低候选人。
- 给出补救策略，例如面试话术、复习重点、简历侧重点。
- 如果 JD 要求 MySQL，而 `cv.md` 中 PostgreSQL 更强，要诚实说明“数据库基础可迁移，但需准备 MySQL 差异点”。

## 推荐简历版本

只能选择一个：

- Java后端版
- AI应用版
- 全栈版
- 无推荐简历版本

选择规则：
- Java / Spring Boot / MySQL / Redis / RESTful API 为主：选 **Java后端版**
- LLM / RAG / Agent / Prompt / AI安全 / FastAPI 为主：选 **AI应用版**
- 前端 + 后端 + 联调为主：选 **全栈版**
- 如果投递建议为 **不推荐**：必须选 **无推荐简历版本**，不要建议为该岗位定制简历。

输出：

```text
推荐简历版本：{Java后端版 | AI应用版 | 全栈版 | 无推荐简历版本}
理由：...
```

## 投递建议

只能输出一个：

- 推荐投递
- 谨慎投递
- 不推荐

判断规则：
- 85-100：推荐投递
- 70-84：推荐投递，但指出准备重点
- 55-69：谨慎投递
- 0-54：不推荐

如有培训、外包低质量、虚假 AI 岗、职责含糊、城市/实习条件明显不符，可降级建议。

---

## BOSS沟通开场白

根据投递建议生成内容：

- **推荐投递**：生成 1 条正常 BOSS 直聘开场白。
- **谨慎投递**：生成 1 条询问岗位详情的话术，重点确认技术栈、实习内容、导师/团队安排、城市/到岗要求。
- **不推荐**：不要生成正常求职话术。改为生成“岗位真实性确认问题”。

要求：
- 100-150 字。
- 学生身份。
- 技术真实。
- 简洁自然。
- 不夸大，不用架构师语言。
- 不包含手机号、邮箱等隐私信息。
- 根据 JD 选择强调 Java 后端、AI 应用或全栈。

模板方向：

```text
您好，我是软件工程本科在读，想了解这个{岗位名}实习机会。我有{项目/技术栈}相关项目经验，做过{1-2个真实贡献}，和岗位里的{JD关键词}比较匹配。希望有机会参与实际开发，也想进一步了解团队的实习安排。
```

### 不推荐岗位的真实性确认问题

当投递建议为“不推荐”时，输出 3-5 个问题，不要输出求职开场白：

- 这个岗位是否是真实研发岗位，还是培训/招生/转化岗位？
- 实习生是否会参与实际代码开发和项目迭代？
- 是否有导师或正式开发同学指导？
- 是否涉及收费、培训协议、贷款或入职前付费？
- 岗位日常职责中开发、运营、销售、标注分别占比多少？

## 预计面试问题

按岗位方向输出问题。

### Java方向

必须覆盖：
- Java基础
- Spring Boot
- MySQL
- Redis
- 事务
- 项目追问

示例方向：
- Java 集合、异常处理、面向对象怎么理解？
- Spring Boot 如何设计 RESTful API？
- 事务控制库存扣减时如何避免数据不一致？
- 行级锁如何解决库存超卖？
- Redis 验证码和限流怎么设计？
- 图书管理系统中你作为项目组长具体负责什么？

### AI方向

如果 JD 包含 AI/LLM/RAG/Agent，必须覆盖：
- LLM
- RAG
- Prompt
- Agent
- AI安全

示例方向：
- LLM API 调用流程是什么？
- RAG 知识库一般由哪些模块组成？
- Prompt Injection 是什么，Dietapp 中如何做风险识别？
- Agent 工具调用和普通对话有什么区别？
- AI 安全分析如何输出结构化风险提示？

---

## 风险提示

如果 JD 有以下情况，必须明确提示：
- 培训、招生、贷款、先付费。
- 外包/驻场但职责不清。
- 标题是 AI 应用，实际做运营、标注、销售、客服。
- 要求远高于本科实习岗位。
- 城市、到岗、周期不明确。

---

## 输出约束

- 使用中文。
- 不输出旧版 A-G 高级岗位格式。
- 不使用 LinkedIn、Glassdoor、Levels.fyi 等海外求职默认语境，除非用户明确要求。
- 不自动投递。
- 如果信息不足，写“未提供”或“无法判断”，不要猜。
